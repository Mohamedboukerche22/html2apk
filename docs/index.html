A zero-host command line tool

Your HTML website,
as an Android app.

Point html2apk at a folder of HTML, CSS and JavaScript and it gives you a signed .apk file. The page runs inside a WebView, so your code works exactly like it does in the browser. No app store, no accounts, no hosting.

A tiny app, your real web code

Same files

Everything in your folder gets bundled as-is. index.html, style.css, app.js, images — untouched. Refreshing the app ships a new APK.

Real browser engine

Pages render in the device WebView. JavaScript, localStorage, CSS grids, offline storage — if it works in Chrome, it works in the app.

No build system

No Gradle, no Node, no npm install of 900 packages. One Python file talks to the Android build tools directly.

How it works

Two halves get glued together: a small Android app that shows your page, and the APK that is wrapped around it.

1

The container app

html2apk writes one Java Activity that owns a WebView. On launch the Activity loads assets/www/index.html from the app's own private storage. JavaScript is on, the back button walks the page history before leaving the app. That is the whole program.

2

Your site goes in assets

Your files are copied into assets/www/. That folder is embedded in the APK, so the app works offline and does not need to fetch anything on first run. Internet permission is included anyway, for pages that call APIs.

3

Resources & the icon

aapt2 compiles the resources (strings, theme, launcher icons) and links them with the manifest, producing the base APK and a generated R.java.

4

Java to dex

javac compiles the Activity and R.java against Android's android.jar, then d8 converts the bytecode into classes.dex, the format phones actually run.

5

Pack, align, sign

The dex file goes into the APK, zipalign aligns the data, and apksigner signs it with a keystore that html2apk creates the first time you build. A signed APK is what Android will install.

If there is no logo, it draws one

Want an icon but have no image handy? Give the tool a name and it paints one: the first letter of the app name, white on a background colour that is derived from the name itself.

"notes", "webmail", "planner", "zoom", "kiosk" — each name picks its own colour automatically. Same name always gets the same colour.

Every density

Launcher icons are generated for mdpi through xxxhdpi, plus an adaptive icon (foreground + background) for newer Android.

Your real logo

Pass --logo logo.png and the tool reuses your artwork. JPG, PNG and even SVG (converted on the fly) are accepted.

Pick the colour

Not a fan of the picked colour? Force your own with --icon-bg 0F9D58.

Usage

# build from the current folder's index.html
html2apk my-website/

# single HTML file
html2apk page.html -n "My Page"

# set name, logo and output file
html2apk my-website/ -n "My App" -l logo.png -o app.apk

# custom package id, different entry file
html2apk my-website/ --package com.me.app --entry app.html
OptionWhat it does
inputfolder, or a single HTML file
-n, --nameapp name shown under the icon
-l, --logopath to your logo image
-o, --outputoutput APK path
--entryentry HTML file inside the folder (default index.html)
--packageAndroid package id
--icon-bghex colour for the icon background
--min-sdkminimum API level (default 24)
--version-nameversion shown to Android (default 1.0)
--keystoresign with your own key instead of the generated one

Install

One file to clone, one symlink, one pip package. The Android SDK downloads itself on the first build.

git clone https://github.com/Mohamedboukerche22/html2apk.git
cd html2apk
ln -s "$(pwd)/html2apk.py" ~/.local/bin/html2apk
pip install pillow
  • Python 3.9+
  • A JDK in the 17-21 range
  • Pillow, but only for the auto-drawn icon — skip it if you always pass --logo
